### 02. Routing Evolution 수동 지도의 늪에서 벗어나는 파일 시스템 라우팅의 진화

<br>

#### 1. 수동지도의 늪 (도입 전)

---

- **"모든 길을 수첩에 적어야 했던 시절"**
  - Next.js를 쓰기 전에는, 페이지 하나를 만들 때마다 개발자가 직접 '지도'를 그려야했다.
- 배경지식: 귀찮은 수동 배선 작업
  - 예전 방식(React Router) 코드를 확인해보면 아래와 같다.

    ```jsx
    /* [과거의 고통]: 하나하나 직접 연결해야 함 */

    // 1. 페이지를 파일에서 가져온다. (import)
    import Home from "./Home";
    import About from "./About";
    import Mypage from "./Mypage";

    // 2. 주소(URL)와 페이지(Component)를 짝지어준다.
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
      <Route path="/mypage" element={<Mypage />} />
    </Routes>;
    ```

- 문제점
  - 깜빡하면 에러
    - 페이지 파일을 아무리 잘 만들어도, 저 `Routes` 목록에 등록하는 걸 깜박하면 화면이 나오지 않는다. (마치 건물을 지어놓고 지도에 표시를 안 해서 아무도 못 찾아감)
  - 오타의 지옥
    - `/about`을 `/abput`라고 실수로 적으면? 사용자는 영문도 모른 채 "페이지를 찾을 수 없습니다(404)"라는 에러만 보게 된다.
  - 관리의 어려움
    - 페이지가 100개가 되면, 저 목록도 100줄이 넘어가서 알아보기가 힘들어진다.

<br>

#### 2. 파일 시스템 라우팅 (도입 후)

---

- **"건물을 지으면 주소가 자동으로 생기는 마법"**
  - Next.js는 이 모든 귀찮은 과정을 없앴다. "폴더의 위치가 곧 주소다"라는 규칙 하나만 기억하면 된다.
- 기술적 실체: 폴더가 곧 지도다
  - `app` 폴더 안에 새로운 폴더를 만들면, 그것이 바로 인터넷 주소가 된다.

    ```md
        /* [현재의 혁명]: Next.js 폴더 구조 */

        app/
        ├── page.tsx               👉 인터넷 주소창: "내사이트.com/"
        ├── about/
        │   └── page.tsx           👉 인터넷 주소창: "내사이트.com/about"
        ├── login/
        │   └── page.tsx           👉 인터넷 주소창: "내사이트.com/login"
    ```

- 핵심 포인트
  - 설정 파일 삭제
    - "이 주소로 오면 저 페이지 보여줘"라고 적던 수첩이 사라졌다.
  - 직관적
    - 폴더 구조만 쓱 훑어봐도 "아, 이 사이트는 소개(about)랑 로그인(login) 페이지가 있구나" 하고 바로 알 수 있다.
  - 자동화
    - 폴더를 만들고 `page.tsx` 파일을 넣는 순간, 전 세계 어디서든 접근 가능한 주소가 생성된다.

#### 3. 만능 열쇠 `[id]` (동적 라우팅)

- **"상품이 1억 개라도 페이지는 하나면 된다"**
  - 쇼핑몰을 만든다고 상상해 보자. 상품이 1억 개다. 그럼 폴더를 1억 개 만들어야 할까? `app/product/1`, `app/product/2`, `app/product/3` ...? **절대 아니다.**
  - 이때 사용하는 것이 바로 대괄호 `[]`이다.
- 동작 원리: 변수형 폴더 (Dynamic Route)
  - 폴더 이름에 대괄호를 씌우면 Next.js는 이렇게 생각한다. "아, 여기엔 뭐가 들어올지 몰라. 들어오는 값을 내가 받아서 페이지에 넘겨줄게!"
    ```md
        app/
        └── products/
            └── [id]/      👈 "여기는 어떤 단어든 들어올 수 있어!" (만능 폴더)
                └── page.tsx
    ```
- 시뮬레이션: 사용자가 접속할 때 일어나는 일

  1\) 사용자가 주소창에 `내 사이트.com/products/galaxy`라고 입력한다.

  2\) Next.js가 `products` 폴더로 간다.

  3\) 그 안에 `galaxy`라는 폴더는 없지만 `[id]`라는 **만능 폴더**가 있다.

  4\) Next.js가 말한다. **"자, [id] 폴더야. 사용자가 방금 galaxy라고 입력했어. 이 단어를 params라는 봉투에 담아줄 테니 화면에 띄워!"**

  5\) 페이지는 봉투를 열어보고 "아, 갤럭시 상품을 보여달라는구나!" 하고 알아챈다.

- 비유: 호텔 프런트 vs 아파트 호수
  - 이 차이를 가장 쉽게 이해하는 비유다.
  - **과거 (수동 라우팅): 호텔 프런트**
    - 손님(사용자)이 오면 프런트 직원이 장부를 뒤적이며 "301호 손님은... 저쪽 복도로 가세요"라고 안내해야 한다.
    - 직원이 실수로 장부에 방을 안 적어두면, 손님은 방을 못 찾는다..
  - **현재 (파일 시스템 라우팅): 아파트 호수**
    - 별도 안내가 필요 없다. '101동 202호'라는 주소(폴더 경로)만 있으면 배달원(브라우저)이 정확히 찾아간다.
    - 건물(폴더)만 지어져 있다면 무조건 찾아갈 수 있다.
  - **동적 라우팅 [id]: 빈 명찰**
    - "방문객"이라고 적힌 빈 명찰이다. 철수가 오면 '철수'가 되고, 영희가 오면 '영희'가 되는 만능 명찰이다.
