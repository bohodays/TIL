### 16. 이벤트 루프와 마이크로태스크·매크로태스크 큐

<br>

#### 1. 싱글 스레드인데 어떻게 안 막히지?

---

- 자바스크립트 엔진은 **콜 스택(Call Stack)이 하나뿐인 싱글 스레드**다. 그런데도 `setTimeout`, `fetch`, 클릭 이벤트 같은 비동기 작업이 메인 스레드를 막지 않고 돌아가는 것처럼 보인다. 이걸 가능하게 하는 게 **이벤트 루프(Event Loop)** 다.
  > 찰떡 비유: 요리사는 한 명뿐인 주방
- 주방(콜 스택)에는 요리사가 딱 한 명이다. 주문(비동기 작업)이 들어오면 요리사가 직접 만들지 않고, 타이머 담당·서빙 담당(브라우저/Node의 Web API, libuv 등)에게 위임한 뒤 바로 다음 주문을 받는다. 위임했던 작업이 끝나면 곧장 요리사 손에 쥐어지는 게 아니라, 순서대로 대기하는 **큐**에 먼저 줄을 선다. 요리사는 자기 앞의 일(콜 스택)이 완전히 빌 때마다 큐를 확인해서 다음 일을 하나씩 가져온다 — 이 "확인하고 가져오는" 무한 반복이 이벤트 루프다.
- MDN은 이 구조를 다음과 같이 정의한다.
  > "The event loop got its name because of how it's usually implemented, which usually resembles: `while (queue.waitForMessage()) { queue.processNextMessage(); }`"
  > 이벤트 루프는 큐에 메시지가 올 때까지 기다렸다가, 도착하면 하나씩 꺼내 처리하는 반복문 형태로 흔히 구현된다.

<br>

#### 2. 두 개의 대기줄, 매크로태스크 큐 vs 마이크로태스크 큐

---

- 그런데 이 대기줄이 사실 하나가 아니라 **둘**이다. `setTimeout`/`setInterval`, DOM 이벤트, `fetch`의 콜백 등은 **매크로태스크(Macrotask) 큐**에 줄을 서고, `Promise.then/catch/finally`, `queueMicrotask()`, `MutationObserver`는 **마이크로태스크(Microtask) 큐**라는 별도의 줄을 선다.
  > 찰떡 비유: 일반 손님 줄과 VIP 줄
- 놀이공원 매표소를 떠올려보자. 매크로태스크는 **일반 대기줄**이고, 마이크로태스크는 **VIP 패스 줄**이다. 규칙은 단순하다 — _"매표소 직원(콜 스택)은 한 명을 응대해서 완전히 끝낼 때마다, 일반 줄로 넘어가기 전에 VIP 줄이 텅 빌 때까지 무조건 먼저 처리한다."_
- 즉 실행 순서는 다음과 같다.
  1. 현재 실행 중인 스크립트(또는 매크로태스크 하나)를 끝까지 실행한다.
  2. 마이크로태스크 큐에 쌓인 작업을 **큐가 완전히 빌 때까지** 전부 처리한다. (처리 중에 새 마이크로태스크가 추가되면 그것도 이번 라운드에 마저 처리한다.)
  3. 그제서야 매크로태스크 큐에서 딱 하나를 꺼내 실행하고, 다시 2번으로 돌아간다.

<br>

#### 3. 코드로 확인하는 실행 순서

---

```javascript
console.log("1. 동기 코드 (콜 스택)");

setTimeout(() => {
  console.log("4. setTimeout - 매크로태스크");
}, 0);

Promise.resolve().then(() => {
  console.log("3. Promise.then - 마이크로태스크");
});

queueMicrotask(() => {
  console.log("2.5. queueMicrotask - 마이크로태스크");
});

console.log("2. 동기 코드 (콜 스택)");

// 실행 결과:
// 1. 동기 코드 (콜 스택)
// 2. 동기 코드 (콜 스택)
// 2.5. queueMicrotask - 마이크로태스크
// 3. Promise.then - 마이크로태스크
// 4. setTimeout - 매크로태스크
```

- `setTimeout(fn, 0)`은 "0ms 뒤 즉시 실행"이 아니라 "지금 실행 중인 동기 코드 + 모든 마이크로태스크가 끝난 뒤, 매크로태스크 큐 차례가 왔을 때 실행"이라는 뜻이다. 이 순서를 모르면 "분명 0ms인데 왜 Promise보다 늦게 찍히지?" 하는 흔한 삽질을 하게 된다.

<br>

#### 4. 실무에서 걸려 넘어지는 함정 — 마이크로태스크 무한 루프

---

- 마이크로태스크 큐는 **완전히 빌 때까지 절대 양보하지 않는다.** 그 말은, 마이크로태스크 안에서 계속 새로운 마이크로태스크를 만들어내면 브라우저가 화면을 다시 그리거나(리페인트) 다음 매크로태스크로 넘어갈 기회를 영영 얻지 못한다는 뜻이다.

```javascript
/* ❌ [안티 패턴] 마이크로태스크 큐를 절대 비우지 못하게 만드는 코드 */
function loopForever() {
  Promise.resolve().then(loopForever);
}
loopForever();
// 콜 스택은 계속 비지만, 마이크로태스크 큐가 절대 비지 않는다.
// → 브라우저는 렌더링은커녕 setTimeout, 클릭 이벤트조차 처리할 기회를 얻지 못하고 사실상 멈춘다.
```

```javascript
/* ✅ [해결책] 매크로태스크로 한 박자 양보하기 */
function loopWithYield() {
  // setTimeout(fn, 0)은 매크로태스크 큐로 들어가므로,
  // 그 사이 브라우저가 렌더링/이벤트 처리를 할 틈을 확보할 수 있다.
  setTimeout(loopWithYield, 0);
}
loopWithYield();
```

- 대량의 데이터를 `.then()` 체인으로 재귀 처리하거나, 상태 관리 라이브러리가 내부적으로 Promise 마이크로태스크를 연쇄적으로 쏘는 패턴에서 이런 문제가 은근히 자주 발생한다. 화면이 순간적으로 버벅이거나 입력 이벤트가 씹히는 버그를 마주치면, 마이크로태스크 큐가 계속 채워지고 있는 건 아닌지 의심해볼 가치가 있다.

<br>

#### 5. 정리

---

- **콜 스택**: 지금 당장 실행되는 동기 코드가 쌓이는 곳. 싱글 스레드이므로 하나뿐이다.
- **마이크로태스크 큐**: `Promise` 후속 처리, `queueMicrotask`. 콜 스택이 빌 때마다 **큐가 텅 빌 때까지** 먼저 처리된다.
- **매크로태스크 큐**: `setTimeout/setInterval`, I/O, 이벤트 콜백. 마이크로태스크 큐를 다 비운 뒤에야 **딱 하나**씩 처리된다.
- 우선순위: `동기 코드 > 마이크로태스크(전부) > 매크로태스크(하나) > (다시 마이크로태스크 확인) > ...` 이 사이클이 이벤트 루프의 정체다.
