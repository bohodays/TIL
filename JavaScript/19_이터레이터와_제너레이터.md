### 19. 이터레이터와 제너레이터

<br>

#### 1. 이터레이터 프로토콜 — `for...of`가 내부적으로 하는 일

---

- `for...of`, 전개 구문(`...`), 구조 분해 할당, `Array.from` 같은 문법은 배열마다 따로 순회 로직을 아는 게 아니다. 이들은 모두 **이터레이터 프로토콜(iterator protocol)** 이라는 공통 인터페이스에만 의존한다.
- 이터레이터란 `next()` 메서드를 가진 객체이고, `next()`는 호출할 때마다 `{ value, done }` 형태의 객체를 반환해야 한다는 규약이다.
  > "An object is an iterator when it implements a `next()` method with the following semantics..."
  > 객체가 다음과 같은 의미를 갖는 `next()` 메서드를 구현하고 있으면 그 객체는 이터레이터다.
- 배열의 이터레이터를 직접 꺼내 수동으로 순회해보면 `for...of`가 반복해서 호출하는 게 정확히 이 `next()`라는 걸 알 수 있다.

```javascript
const arr = ["a", "b"];
const iterator = arr[Symbol.iterator](); // 이터레이터를 직접 꺼낸다

iterator.next(); // { value: "a", done: false }
iterator.next(); // { value: "b", done: false }
iterator.next(); // { value: undefined, done: true }
```

- `done: true`가 반환되면 순회는 그걸로 끝이다. `for...of`는 이 반환값을 보고 언제 루프를 멈출지 판단할 뿐, 배열인지 `Map`인지 커스텀 객체인지는 전혀 신경 쓰지 않는다.

<br>

#### 2. 이터러블 프로토콜 — 커스텀 객체를 `for...of`에 태우기

---

- 이터레이터 프로토콜이 "어떻게 하나씩 꺼낼지"를 정의한다면, **이터러블 프로토콜(iterable protocol)** 은 "이터레이터를 어디서 구할지"를 정의한다. 객체가 `Symbol.iterator`라는 키에 이터레이터를 반환하는 함수를 갖고 있으면 그 객체는 이터러블이다.
- 일반 객체 리터럴 `{}`는 기본적으로 이 메서드가 없어서 `for...of`에 넣으면 `TypeError`가 난다. 반대로 말하면, `Symbol.iterator`만 구현해주면 배열이 아닌 어떤 객체도 `for...of`·전개 구문에 태울 수 있다는 뜻이다.

```javascript
const range = {
  from: 1,
  to: 3,
  [Symbol.iterator]() {
    let current = this.from;
    const last = this.to;
    return {
      next() {
        return current <= last
          ? { value: current++, done: false }
          : { value: undefined, done: true };
      },
    };
  },
};

for (const num of range) console.log(num); // 1, 2, 3
[...range]; // [1, 2, 3] — 전개 구문도 동일하게 동작
```

- 배열, 문자열, `Map`, `Set`, `arguments`, DOM의 `NodeList` 모두 각자 다른 내부 구현을 갖고 있지만 전부 이 두 프로토콜(이터러블·이터레이터)만 지키기 때문에 `for...of` 하나로 통일해서 순회할 수 있는 것이다.

<br>

#### 3. 제너레이터 — 이터레이터를 손으로 안 짜도 되게 해주는 문법

---

- 위 `range` 예제처럼 `next()`와 `current`, `done` 판단 로직을 매번 손으로 짜는 건 번거롭다. **제너레이터 함수(`function*`)** 는 이 보일러플레이트를 문법 차원에서 없애준다.
  > 찰떡 비유: 한 번에 다 안 주고 부를 때마다 꺼내주는 자판기
- 일반 함수는 호출하는 즉시 끝까지 실행돼서 값을 한 번에 반환한다. 제너레이터 함수는 호출해도 코드가 실행되지 않고, 대신 **제너레이터 객체**(이터레이터이자 이터러블)를 돌려준다. 이후 `next()`를 부를 때마다 자판기 버튼을 누르듯 `yield`를 만날 때까지만 딱 실행하고, 그 자리에서 실행을 멈춘 채(suspended) 다음 호출을 기다린다.

```javascript
function* rangeGen(from, to) {
  for (let i = from; i <= to; i++) {
    yield i; // 여기서 실행이 멈추고 i를 반환한다
  }
}

const gen = rangeGen(1, 3);
gen.next(); // { value: 1, done: false }
gen.next(); // { value: 2, done: false }
gen.next(); // { value: 3, done: false }
gen.next(); // { value: undefined, done: true }

// 제너레이터 객체 자체가 Symbol.iterator를 갖고 있어 for...of에 바로 쓸 수 있다.
for (const n of rangeGen(1, 3)) console.log(n); // 1, 2, 3
```

- `return`으로 도중에 끝내면 그 값이 마지막 `{ value, done: true }`의 `value`가 되고, 이후 `next()`를 더 호출해도 계속 `done: true`만 돌아온다.

<br>

#### 4. `next()`에 값 전달하기 — 양방향 통신

---

- `yield`는 값을 밖으로 내보내기만 하는 게 아니라, `next(value)`로 전달한 인자를 **표현식의 결과값**으로 돌려받을 수도 있다. 즉 제너레이터 안팎이 서로 값을 주고받는 양방향 채널이 된다.

```javascript
function* asker() {
  const name = yield "이름이 뭐예요?";
  const age = yield `${name}님, 나이는요?`;
  return `${name}(${age}세)님 반갑습니다.`;
}

const it = asker();
console.log(it.next().value); // "이름이 뭐예요?" (첫 next는 인자를 넘겨도 무시된다)
console.log(it.next("길동").value); // "길동님, 나이는요?"
console.log(it.next(30).value); // "길동(30세)님 반갑습니다."
```

- 첫 `next()`는 아직 첫 `yield`에 도달하기 전이라 넘긴 인자를 받아줄 곳이 없다. `next(v)`가 채우는 건 **직전에 멈춰있던 `yield` 표현식의 값**이기 때문에, 항상 한 턴씩 밀려서 대응된다는 점이 실수하기 쉬운 부분이다.
- 이 양방향성 덕분에 제너레이터는 `redux-saga` 같은 라이브러리에서 "비동기 작업을 실행하고, 그 결과를 다시 제너레이터 안으로 넣어준 뒤 이어서 실행한다"는 패턴의 기반으로 쓰였다. `async/await`도 개념적으로는 이 구조 위에 문법을 얹은 것에 가깝다.

<br>

#### 5. `yield*`로 다른 이터러블에 위임하기

---

- 제너레이터 안에서 다른 이터러블을 순회하며 값을 그대로 전달하고 싶을 때, `for...of` + `yield`를 매번 쓰는 대신 `yield*`로 위임(delegation)할 수 있다.

```javascript
function* inner() {
  yield "a";
  yield "b";
}

function* outer() {
  yield 1;
  yield* inner(); // inner의 각 yield를 그대로 이어받아 내보낸다
  yield 2;
}

[...outer()]; // [1, "a", "b", 2]
```

- `yield*`가 위임하는 동안에는 바깥쪽 `next()` 호출이 그대로 안쪽 이터레이터의 `next()` 호출로 전달된다. 배열뿐 아니라 문자열, `Map`, 다른 제너레이터 등 이터러블이기만 하면 무엇이든 위임 대상이 될 수 있어서, 트리 구조를 재귀적으로 순회하는 제너레이터를 짤 때 특히 유용하다.

```javascript
function* flatten(tree) {
  for (const node of tree) {
    if (Array.isArray(node)) {
      yield* flatten(node); // 중첩 배열을 재귀적으로 위임
    } else {
      yield node;
    }
  }
}

[...flatten([1, [2, 3, [4, 5]], 6])]; // [1, 2, 3, 4, 5, 6]
```

#### 6. 실무 활용 — 지연 평가(lazy evaluation)와 무한 시퀀스

---

- 제너레이터의 가장 실질적인 이점은 **값을 미리 전부 만들지 않고, 필요한 시점에 딱 하나씩만 계산한다**는 것이다. 배열을 반환하는 함수는 호출 즉시 전체 결과를 메모리에 올려야 하지만, 제너레이터는 `next()`가 불릴 때만 다음 값을 계산하므로 끝이 없는 시퀀스도 자연스럽게 표현할 수 있다.

```javascript
function* naturalNumbers() {
  let n = 1;
  while (true) {
    yield n++;
  }
}

function take(iterable, count) {
  const result = [];
  for (const value of iterable) {
    if (result.length >= count) break;
    result.push(value);
  }
  return result;
}

take(naturalNumbers(), 5); // [1, 2, 3, 4, 5] — 무한 제너레이터에서 필요한 만큼만 소비
```

- 이 성질은 대용량 로그를 한 줄씩 처리하거나, 커서 기반 페이지네이션을 순차적으로 소비하는 등 "전체를 한 번에 들고 있을 필요 없는" 데이터 흐름에 잘 맞는다.
- 비동기 버전인 **`async function*`(비동기 제너레이터)** 은 `yield` 대신 `for await...of`로 소비하며, `Promise`를 하나씩 순차적으로 풀어내야 하는 스트리밍 응답이나 파일 스트림 처리에 쓰인다. 기본 골격은 동기 제너레이터와 동일하고, `next()`가 `Promise`를 반환한다는 점만 다르다.

<br>

#### 7. 정리

---

- **이터레이터 프로토콜**(`next()` → `{ value, done }`)과 **이터러블 프로토콜**(`Symbol.iterator` → 이터레이터 반환)은 서로 다른 규약이며, `for...of`·전개 구문·구조 분해는 오직 이 두 규약에만 의존해 동작한다.
- 제너레이터 함수(`function*`)는 이 두 프로토콜을 자동으로 만족하는 객체를 만들어주는 문법 설탕이라, 커스텀 이터러블을 손으로 구현하는 보일러플레이트를 크게 줄여준다.
- `yield`는 값을 밖으로 내보내는 동시에 `next(value)`로 받은 값을 안으로 들여오는 양방향 통신 지점이며, `yield*`는 다른 이터러블에 순회를 그대로 위임한다.
- 값을 미리 다 계산하지 않고 요청받을 때마다 하나씩 만드는 **지연 평가** 특성 덕분에 무한 시퀀스나 대용량 스트림 처리에 적합하고, 비동기 버전(`async function*` + `for await...of`)은 스트리밍 데이터 처리에 쓰인다.
